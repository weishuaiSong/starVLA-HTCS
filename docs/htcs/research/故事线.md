## 一、问题动机：VLA 历史压缩的共同盲点

真实世界的机器人操作普遍**违反马尔可夫假设**——遮挡导致任务相关状态部分可观测、多步流程携带隐式进度、自然语言指令本身就常引用过去事件（"now put it down"）。近一年 VLA 工作已形成共识：单帧观测不足以支撑长程操作，**历史上下文对于部分可观测的消解、长程规划、in-context 适应都是必要的**（MEM、HiF-VLA、MemoryVLA、π0.7 均明确指出这一点）。然而朴素堆叠多帧已被反复观察到会**损害而非帮助性能**——它膨胀 VLM token 预算、稀释 attention、放大对历史无关线索的过拟合。**问题不在"要不要用历史"，而在"如何压缩历史"**。

近一年视觉历史压缩方向有两条路线同时崛起：

- **压缩路线**：HiF-VLA（CVPR 2026，MV 作 VLA 历史输入）、OneVision-Encoder（HEVC 启发的 patch 选择）、CoPE-VideoLM（codec 的 I/P 帧二分作 token 预算）——把视觉压缩做成更精细的稀疏化
- **记忆路线**：MEM（PI 2026.03）、π0.7（PI 2026.04，沿用 MEM）、MemoryVLA、ReMem-VLA——把短期密集编码 + 长期摘要分尺度处理

**这两条路线有一个共同盲点：短期视觉编码器全部任务无关**。无论指令是"抓黑碗"还是"放酒瓶"，同一段历史观测在所有方法里都用同一套压缩规则。任务条件化要么完全没有，要么只发生在压缩之后的末端融合层。

MEM 是这个盲点最具揭示性的反例：它的 π_HL 在 chain-of-thought 解码中**持续产出任务相关的语言信号**（子指令 l_t + 滚动摘要 m_t），但这些信号只往动作端流动，**从未回流去条件化视觉感知**。架构上语言信号唾手可得，却整条路线全员错过了利用它的机会。

## 二、核心洞察：语言条件化有不同 granularity

任务条件化不是单一操作，而是**有不同 granularity 的层级**：

- **参数级**（决定"看哪种运动"）：codec 信号本身有多个分量（MV 模长、MV 方向、Residual），不同任务对它们的相对重要性不同——"推"类任务关注大幅 MV，"精细放置"任务关注接触瞬间的 Residual，"推左 vs 推右"则模长相同但方向相反
- **结构级**（决定"看哪些 patch"）：在每帧的具体 patch 上做选择——"放到柜子顶部"的语言让 attention 锁定柜子区域，"抓黑碗"则锁定碗周围

两个 granularity 互补、不冗余、且**都只需要语言信号**（不依赖 proprioception）。

## 三、方法：HTCS 闭合 perception-conditioning 回路

HTCS 把两个 granularity 串联到 codec 压缩流水线：

```
T 帧历史 ──HEVC──► I-frame RGB + P-frame MV (二维) + Residual
                                ↓
                Stage 1：参数级语言条件化 codec saliency
                s = α(ℓ)·‖MV‖ + γ(ℓ)·(MV·v_tgt(ℓ)) + β(ℓ)·|Residual|
                所有权重 (α, β, γ, v_tgt) 从语言派生
                                ↓
                稀疏 patch 集 P (~600 patches)
                                ↓
                Stage 2：结构级语言条件化 patch 压缩
                K 个 slot 由语言序列经 MHA 派生
                与 P 做 competitive softmax cross-attention
                                ↓
                K 个任务相关摘要词元 H
                                ↓
                M4 cross-attention 注入动作查询 → 动作头 → a_t
```

**Stage 1 的关键技术点**：方向项 γ·(MV·v_tgt) 是 manipulation 场景特有的关键信号——"推左 vs 推右"的 ‖MV‖ 完全相同，但 v_tgt 相反；所有 codec-based VLA 工作（HiF-VLA、OneVision、CoPE、CoViAR 系列）都"取 MV 模长丢方向"，这是整个方向的集体盲点。

**Stage 2 的关键技术点**：K 个 slot 必须由**语言序列**派生（非池化），与 Stage 1 输出做 competitive softmax cross-attention——E1 反事实指令替换实验是这一设计的命门：如果语言条件能仅靠末端融合获得，结构级语言条件化就是装饰；反之，必须显式嵌入压缩阶段。

## 四、三条核心贡献

> **粒度对齐参考**：HiF-VLA、MemoryVLA 均为 3 条 mid-granularity（系统级 framework + 单一核心机制 + 实验/经验）。本工作沿用同一模板。

### C1（系统级 framing）：HTCS——首个任务条件化的 VLA 历史压缩框架

我们识别并填补 VLA 历史压缩的核心空白：所有现有方法（压缩路线 + 记忆路线）的短期视觉编码器均为任务无关。HTCS 是第一个把任务语言信号显式注入短期视觉历史压缩的 VLA 框架，闭合 perception-conditioning 回路。

### C2（核心机制）：Bi-Granularity Language Conditioning

参数级（方向感知 codec saliency）+ 结构级（语言派生 K query 的 cross-attention）级联——两个 granularity 正交非冗余，且结构级条件不能仅靠末端融合获得（必须显式嵌入压缩阶段）。

### C3（实验 + 组合性）：作为 Plug-in 低层模块的 Dual-System VLA 集成

将 HTCS 实证为现代 dual-system VLA 栈的即插即用低层感知模块：

1. **Sub-instruction switching probe**：用教师 LLM 离线分解 LIBERO-Long 任务模拟 planner 输出，验证 HTCS 接受 planner 风格子指令时压缩行为相应自适应
2. **Adapter 集成实证**：在一个公开 VLA ckpt 上以冻结 backbone + LoRA 完成轻量微调集成

主基准 LIBERO + 第二基准 CALVIN ABC-D，与上述两层 plug-in 证据配套呈现。

## 五、定位：与现有 VLA 栈的双重正交

HTCS 在两个独立维度上正交于现有工作，使其可作为模块即插即用：

### 维度 A：与高层任务规划器正交
现代 VLA 已收敛到 dual-system 架构（Hi Robot、π0.5/π0.6、Gemini Robotics 1.5、MEM π_HL）——高层 VLM planner 以 1–10 Hz 输出语言子指令，低层 visuomotor policy 以 50–200 Hz 执行。HTCS 是低层 policy 内部的历史压缩模块，**天然消费上层 planner 输出的子指令作为语言条件 ℓ**。

### 维度 B：与长期记忆抽象层正交
纯记忆架构工作（MEM、MemoryVLA、ReMem-VLA、MemER）均为短期 + 长期双层结构。其中短期层是相对朴素的密集编码（MEM 的 ViT 时空注意力、MemoryVLA 的工作记忆 token），**HTCS 恰好是它们短期层的高质量替代**。

两个维度的正交是独立的：A 是沿任务向前分解，B 是沿时间向后回溯。HTCS 同时与两者正交，意味着它能在"上层 planner + HTCS + 长期记忆"这样的三层架构中作为中间感知层即插即用。

## 八、Scope 边界（防 overclaim）

诚实声明本文不做的事：

- **不**集成进 planner ckpt 端到端联动——用 LLM 伪造子指令验证接口（C3-a）
- **只在 1 个公开 VLA ckpt 上**做 adapter 集成（C3-b）；多 ckpt 集成留 follow-up
- **不**做真实 planner 实时联动（如真 π0.5 + HTCS）——留下一篇工作
- **不**做长期记忆联合训练——本文所有数字基于 HTCS 作为独立短期层评估；多尺度联合训练是 future work
