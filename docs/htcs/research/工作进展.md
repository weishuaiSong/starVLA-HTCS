## 二、Framing 与 Contribution 结构演化

### 第一版：6 条窄粒度 claim（C1–C6）
最早整理：双 granularity / 命门 / 非冗余 / 一致性增益 / 参数级非平凡 / 方向感知非平凡。
**问题**：粒度太细，C1/C2 是同一机制的两半，违反 HiF-VLA / MemoryVLA 的 3 条 mid-granularity 行业惯例。

### 第二版：拆 C1 为两条正交贡献
按 granularity 拆参数级 + 结构级为独立贡献，加 plug-in 接口为第三条。
**问题**：参数级方向感知 saliency 是"机制细节"不够当 paper-level contribution；reviewer 会觉得粒度不够。

### 第三版（当前）：对齐 HiF-VLA / MemoryVLA 的 3 条 mid-granularity 模板
- **C1（系统级 framing）**：HTCS——首个任务条件化的 VLA 历史压缩框架，闭合 perception-conditioning 回路
- **C2（核心机制）**：Bi-granularity language conditioning（参数级 + 结构级合并为一条机制，方向感知是 C2 内的 sub-claim）
- **C3（实验 + 组合性）**：plug-in 低层模块——sub-instruction switching probe + adapter 集成 + CALVIN 第二基准

## 三、关键 framing insight 沉淀

### Insight 1：MEM 的 π_HL 是最具揭示性的反例
MEM 的 chain-of-thought 解码已经在源源不断输出任务相关语言信号（子指令 l_t + 滚动摘要 m_t），但这些信号**只往动作端流动，从未回流条件化视觉感知**。这把"现有 VLA 历史压缩任务无关"从泛泛的对照升级成有具体反例的硬批判——本工作的核心 framing 由此立起。

### Insight 2：MEM 长期层是 chain-of-thought，不是外置 LLM
通过查 PI 官方页 + MarkTechPost 解读厘清：MEM 的"长期语言摘要"是**VLA 内部 π_HL 自回归生成**（与 π_LL 共享 Gemma 3-4B backbone），训练时用教师 LLM 摘要作监督；**推理时无外部 LLM 调用**。这影响 §7 多尺度组合的措辞。

### Insight 3：MEM 同时承担 memory + planner 两个角色
MEM 的 π_HL 不仅做长期记忆摘要，还输出子指令 l_{t+1}——把"长期记忆抽象"和"任务规划"合并到同一个 chain-of-thought 模块。这与 Hi Robot / Gemini Robotics 1.5（planner 独立、不管 memory）是不同范式。

### Insight 4：HTCS 与现有 VLA 栈的双重正交
- **维度 A**：与高层任务规划器正交（消费 planner 输出的子指令作 ℓ）
- **维度 B**：与长期记忆抽象层正交（替换 MEM-style 多尺度系统的短期层）

两个维度独立——A 沿任务向前分解，B 沿时间向后回溯。这让 HTCS 能在"planner + HTCS + 长期记忆"三层架构中即插即用。

### Insight 5：行业 contribution 粒度参考
HiF-VLA / MemoryVLA 均为 **3 条 mid-granularity**：系统级 framework + 单一核心机制 + 实验/经验。OneVision-Encoder 4 条（加训练目标）。MEM / π0.7 / Hi Robot 不列举（大实验室风格）。**3 条对标 HiF-VLA / MemoryVLA 是最稳的模板**。
