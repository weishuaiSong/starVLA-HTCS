# 新工作：语言条件化的历史压缩（Language-Conditioned History Compression for VLA）

> **工作文档**。用于持续维护当前的故事、模块、数据流、待决策项与风险。
>
> **方法名**：**HTCS — Hierarchical Task-Conditioned Selection（任务导向的层次筛选）**
> **VLM backbone**：Qwen3-VL-0.8B
> **关键设计原则**：**仅依赖语言信号，不使用 proprioception**——确保部署友好、跨平台通用、人类示范视频兼容
> **基线工作**：MoSA-VLA（见 `MoSA-VLA-新工作初稿.md`）
> **关键对照工作**：HiF-VLA（CVPR 2026，actual codec input）、OneVision-Encoder（codec-based patch selection）、CoPE-VideoLM（codec-based token allocation）、π0.7（PI 2026.04，MEM-style 历史 + 进 VLM 的最强参考）

---

## 0. 一句话故事

> **语言条件化在 VLA 历史压缩中有两个不同 granularity：参数级（决定"看哪种运动"）和结构级（决定"看哪些 patch"）。本工作首次显式分离这两层并级联到 codec 压缩流水线——Stage 1 用语言派生权重调制 codec saliency（参数级），Stage 2 用语言派生 query 做 patch 选择（结构级），共同填补现有 codec/memory-based VLA（HiF-VLA / OneVision-Encoder / CoPE-VideoLM / π0.7 等）"任务无关"的共同盲点。整个方法不依赖任何本体信息，部署/迁移友好。**

---

## 1. 故事三段式

### 1.1 投稿用开篇 framing

> Codec-inspired 视觉压缩这一思想，最近在**三条相对独立的技术路线、跨两个社区**被同时合法化：
>
> - **路线 A（VLA / actual feature input）**：HiF-VLA（CVPR 2026）首次将 MPEG-4 运动向量作为 VLA 的历史输入；
> - **路线 B（video LLM / patch selection）**：OneVision-Encoder（2026）将 HEVC 启发的稀疏化原则提升为多模态架构基础原则，实现 75–98% token 压缩；
> - **路线 C（video LLM / token allocation）**：CoPE-VideoLM（2026.02）把 codec 的 I/P-frame 二分结构作为 token 预算分配规则。
>
> 然而，这三条路线**均面临同一盲点：压缩过程任务无关**。同一段历史观测，无论指令是"抓黑碗"还是"放酒瓶"，都用同一套压缩规则。本工作主张：**语言条件化在 codec 压缩中应有不同 granularity**——分为**参数级**（决定"看哪种运动"）和**结构级**（决定"看哪些 patch"）。我们提出 **Hierarchical Task-Conditioned Selection (HTCS)**：Stage 1 用语言派生权重 \(\alpha(\ell), \beta(\ell)\) 调制 codec saliency 的 MV/Residual 分量比重（参数级），Stage 2 用语言派生 K 个 query 与 Stage 1 输出做 cross-attention（结构级），最终输出 K 个任务相关摘要词元。两层共同填补共同盲点，**且仅依赖语言信号，不需要本体信息**——这使得方法在跨平台和人类示范视频场景下保持可用。

### 1.2 故事三段式

1. **从哪里来**：所有 codec/memory-based VLA（HiF-VLA、OneVision-Encoder、CoPE-VideoLM、π0.7、MEM、MemoryVLA、ReMem-VLA、CronusVLA）的历史压缩**全部任务无关**。MoSA-VLA 也是。这是整个研究方向的共同盲点。
2. **关键洞察**：**语言条件化不是单一操作，而是有不同 granularity 的层级**——
   - **参数级**（决定"看哪种运动"）：codec 信号本身有多个分量（MV、Residual），不同任务对它们的相对重要性不同——"推"类任务关注大幅 MV，"精细放置"任务关注接触瞬间的 Residual。语言可以**在参数层面调制 saliency 公式的权重**。
   - **结构级**（决定"看哪些 patch"）：在每帧的具体 patch 上做选择——"放到柜子顶部"的语言会让 attention 锁定柜子区域。语言可以**在 patch 层面派生 query 做 cross-attention**。

   两个 granularity 互补、不冗余、且不需要本体信息。
3. **解决什么**：HTCS = **Hierarchical Task-Conditioned Selection（任务导向的层次筛选）**（纯语言驱动版本，不依赖 proprio）：
   - **Stage 1**：参数级语言条件化 codec saliency——\(s = \alpha(\ell)\|\text{MV}\| + \beta(\ell)|\text{Residual}|\)，权重 \(\alpha(\ell), \beta(\ell)\) 从语言派生
   - **Stage 2**：结构级语言条件化 patch 压缩——语言派生 K 个 query 与 Stage 1 输出做 cross-attention

   通过反事实测试（E1）+ patch 集合 IoU 分析（E9）+ language-modulated 参数消融（E13）三重证据，证明两层条件都被真正使用且非冗余。**部署优势：所有 task condition 仅来自语言，无需 proprio 同步——人类示范视频亦可用。**

---

## 2. 核心 Claims

- **C1**：**双 granularity 语言条件压缩**（参数级 + 结构级）显著优于单层任务无关压缩（OneVision-Encoder / HiF-VLA 风格）。
- **C2（命门）**：结构级语言条件**不能仅靠末端跨模态融合获得**——必须显式嵌入压缩阶段（否则就是装饰）。
- **C3（granularity 非冗余）**：参数级权重 \(\alpha(\ell), \beta(\ell)\) **跨任务显著变化**，且 Stage 1 选的 patch 集合与 Stage 2 选的 patch 集合 IoU 低——证明两个 granularity 各自捕获互补信息。
- **C4（一致性增益）**：双 granularity 条件化能改善任务间表现的一致性，特别是对历史依赖差异大的任务（Spatial vs Object）。
- **C5（参数级非平凡）**：language-modulated saliency 比固定权重 saliency 在跨任务平均下有显著增益，且 \(\alpha(\ell), \beta(\ell)\) 的可视化跨 4 套件呈现可解释的模式。

> ⚠️ **C2 是命门**：反事实实验（E1）证明。
> ⚠️ **C3 是双 granularity 非冗余的硬证据**：Stage 1 vs Stage 2 patch IoU + 跨任务 \(\alpha,\beta\) 分布（E9 + E13）。
> ⚠️ **C5 是 Stage 1 升级的合法性**：language-modulated vs 固定权重 saliency 消融（E13）。

## 3. 模块清单

| # | 模块 | 输入 | 输出 | 是否新增 |
|---|---|---|---|---|
| M1 | HEVC 编码 + 提取 codec 副产物 | 历史帧 \(\{I_{t-T},\dots,I_{t-1}\}\) | I-frame RGB + P-frame MV/Residual | 改造 MoSA-VLA（原本只取 MV） |
| **M2** | **Stage 1: Language-modulated codec patch selection** | I-frame RGB + MV/Residual + 语言 ℓ | 稀疏 RGB patch 集 \(P \in \mathbb{R}^{N_{\text{kept}}\times d_p}\)，\(N_{\text{kept}} \ll T \cdot N_{\text{full}}\) | OneVision-Encoder 框架 + 参数级语言条件化升级（部分原创） |
| **M3** | **Stage 2: Language-conditioned patch compression** | \(P\), 语言 \(\ell\) | \(H \in \mathbb{R}^{K\times H_{\text{vlm}}}\) | **本工作核心创新** |
| M4 | 跨模态融合（cross-attention） | 动作查询 \(Q\), \(H\) | \(Q'\) | 沿用 MoSA-VLA |
| M5 | 动作头 MLP | \(Q'\) | 动作 \(a_t\) | 沿用 MoSA-VLA |

**模块来源对照**：
- M1：调整 MoSA-VLA 的 ffmpeg 提取脚本，输出 I-frame RGB + MV + Residual energy（不需要 proprioception）
- M2：在 OneVision-Encoder 的 Codec Patchification 基础上**升级 saliency 函数**——\(s = \alpha(\ell)\|\text{MV}\| + \beta(\ell)|\text{Residual}|\)，权重从语言派生。这是参数级语言条件化
- **M3：结构级语言条件化**——Stage 2 的语言派生 K query + cross-attention
- M4/M5：沿用 MoSA-VLA

**两层贡献分布（避免被指"全是借用"）**：
- M2 的 codec patch selection 框架借自 OneVision-Encoder，但 **saliency 函数的 language-modulated 权重升级（D12）是本工作贡献**——这让 Stage 1 不再是纯借用，且实现了"参数级语言条件"这一全新概念
- M3 全新——结构级语言条件化压缩
- M2 + M3 的双 granularity 语言条件级联架构本身是本工作的核心 framing
- **额外优势**：整个流水线的 task condition 仅来自语言，无需 proprio——部署友好且与人类示范视频兼容

**为什么不是单纯把 OneVision-Encoder + MoSA-VLA 堆起来**：
- OneVision-Encoder 没有 Stage 2，patch selection 完全任务无关
- MoSA-VLA 没有 Stage 1，直接用 MV 作 feature
- 本工作首次把两条路线在压缩流水线里**串联**起来，且加入语言条件化二次筛选——这是 M3 的真正贡献

## 4. 数据流（含张量形状的完整规范）

### 张量符号约定

| 符号 | 含义 | 典型值 |
|---|---|---|
| \(T\) | 历史帧数 | 16 |
| \(B\) | batch size | 8 |
| \(N_{\text{full}}\) | 每帧总 patch 数 | 196（14×14 @ 224²） |
| \(N_{\text{kept}}\) | Stage 1 保留总 patch 数 | ~600（约 19% × T × N_full） |
| \(L_{\ell}\) | 语言 token 数 | 16–32 |
| \(d_p\) | patch embedding 维度 | 1152（SigLIP-Large） |
| \(H_{\text{vlm}}\) | VLM 隐藏维度 | 1536（Qwen3-VL-0.8B）|
| \(K\) | 摘要槽数 | 8 |
| \(C\) | 动作查询数 | 8（action chunking） |
| \(d_a\) | 动作维度 | 7（位姿 6 + 夹爪 1） |

### 模块详解（含张量形状）

**M1 — Codec 提取（CPU 侧）**
```
{I_{t-T},...,I_{t-1}}  ──ffmpeg HEVC──►  GOP（I-frame + P-frame MV/Residual）

输出：
- I-frame RGB           (B, n_I, 3, H_img, W_img)
- P-frame MV            (B, n_P, H/16, W/16, 2)
- P-frame Residual      (B, n_P, H/16, W/16)
```

**M2 — Stage 1：Language-Modulated Codec Patch Selection（参数级语言条件）**
```
[输入]
  - I-frame RGB                  (B, n_I, 3, H_img, W_img)
  - P-frame MV                   (B, n_P, H/16, W/16, 2)
  - P-frame Residual energy      (B, n_P, H/16, W/16)
  - 语言 embedding ℓ_emb         (B, L_text, d_text)  ← 复用 VLM text embedder

[计算]
  1. 参数级语言条件化（D12 核心）：
     ℓ_pooled        = mean_pool(ℓ_emb)                    (B, d_text)
     [α(ℓ), β(ℓ)]    = SaliencyMLP(ℓ_pooled)               (B, 2)
                       通常用 softplus 或 sigmoid 保证非负

  2. Language-modulated saliency 评分（每帧每 patch）：
     s_{i,j,t} = α(ℓ) · ‖MV_{i,j,t}‖₂  +  β(ℓ) · |Residual_{i,j,t}|
                                                            (B, n_P, H/16, W/16)

  3. I-frame：全部 patch 保留                              (B, n_I × N_full, d_p)
  4. P-frame：按 s 排序，保留 top ρ% patch                  (B, ~ρ·n_P·N_full, d_p)
              ρ ≈ 20%
  5. 拼接 I + P patch，附加 3D RoPE [t, h, w]
  6. 同时输出 Stage 1 saliency 的归一化分数 s_stage1，传给 Stage 2 作 attention bias（14.3）

[输出]
  P ∈ ℝ^(B × N_kept × d_p)              N_kept ≈ 600
  s_stage1 ∈ ℝ^(B × N_kept)             保留 patch 对应的 saliency 分数（送 M3）

注：Stage 1 是【参数级语言条件】——不同任务下 α(ℓ), β(ℓ) 不同，
   导致同一段历史在不同指令下产生不同的 patch 集 P。这是 HTCS 的关键设计。
```

**M3 — Stage 2：Language-conditioned patch compression（核心创新）**
```
[输入]
  ℓ_emb: VLM text embedder 的中间产物（直接复用，零额外成本）
         shape (B, L_text, d_text)，L_text ≈ 16–32

[计算 — 应用 D14 三个优化]
  1. K 个 slot 从语言序列派生（14.1，不池化）：
     slots = MHA(Q=learnable_K_queries, K=ℓ_emb, V=ℓ_emb)   (B, K, d_text)
     slots = LinearProj(slots)                               (B, K, d_p)

  2. Stage 1 saliency 作 attention bias（14.3）+
     Slot Attention 竞争性 softmax（14.2）：
     A_logits = (slots · P^T) / √d + λ · s_stage1            (B, K, N_kept)
     A        = softmax_over_slots(A_logits)                 ← 沿 K 维归一
     H_raw    = A · P                                        (B, K, d_p)

  3. 投影到 VLM 维度：
     H = Linear(H_raw)                                       (B, K, H_vlm)

[输出]  H ∈ ℝ^(B × K × H_vlm)
```

**工程关键点（必读）**：
- **语言 token 来源**：直接截获 VLM 的 `text_embedder(input_ids)` 输出，零额外计算
- **新增成本**：slot-from-language 的 MHA 仅 ~0.3M FLOPs（K×L_text=192 元素）——总推理增量 <0.01%
- **梯度回传**：建议初期 `text_embeds.detach()`，保持 VLM 预训练对齐稳定；基线通过后可解冻做实验
- **维度对齐**：d_text（VLM 1536）→ d_p（SigLIP 1152）需要 Linear 投影
- **位置编码**：text_embeds 自带 1D PE，patches 自带 3D RoPE，对齐后直接 cross-attn 即可

**VLM 主路径（与 M3 并行）**
```
I_cur, ℓ ──► VLM ──► Q ∈ ℝ^(B × C × H_vlm)
```

**M4 — 跨模态融合**
```
A   = MultiHeadAttention(Q=Q, K=H, V=H)             (B, C, H_vlm)
Q'  = LayerNorm(Q + A)                              (B, C, H_vlm)
```

**M5 — 动作头**
```
a = MLP_2layer(Q')                                  (B, C, d_a)
```

**损失（训练时）**
```
L = L_action + λ_aux · L_aux
L_action = (1/C) Σᵢ ||âᵢ - aᵢ*||₁                    ← L1，沿用 MoSA-VLA
L_aux    = CrossEntropy(TaskHead(H), task_id)        ← D4 任务分类辅助损失
```

### 流程示意

```

                                                                       ▼

                         └──────────────────┬───────────────────────────┘

                                            │
当前帧 I_cur ──► VLM ──► Q ─────────────────┤
   语言 ℓ ──┘    ↑                          │
            (D2 决定 VLM 是否看语言)          │
                                            ▼
                                     ┌────────────┐
                                     │ M4: 融合     │  cross-attn(Q, H)
                                     └──────┬─────┘
                                            ▼
                              ┌────────────────────────┐

                              └────────────┬───────────┘

```

**关键架构观察**：
- **语言指令 \(\ell\) 在两个位置参与压缩**：
  - **Stage 1（M2）**：经 SaliencyMLP 派生 \(\alpha(\ell), \beta(\ell)\) 调制 saliency 公式 → 决定"看哪种运动"
  - **Stage 2（M3）**：作为 cross-attention 的 K/V 派生 K 个 slot → 决定"看哪些 patch"
- **Stage 1 saliency 分数 s_stage1 不丢弃**——通过 14.3 传给 Stage 2 作 attention bias，强化层级化叙事
- **整个流水线的 task condition 仅来自语言**（不依赖 proprio），通过两个不同 granularity 落地——这正是 HTCS 的核心创新

## 5. 关键设计决策

### D1：M3 (Stage 2) 中语言注入的具体形式
- **当前倾向**：K 个 query 从语言派生，对稀疏 patch 集 \(P\) 做 cross-attention
  - 实现：\(\text{slots} = \text{LangProjector}(\ell_\text{emb}) \in \mathbb{R}^{K \times d}\)；\(H = \text{MHA}(\text{slots}, P, P)\)
  - 好处：结构上强制依赖语言，鉴别力最强

### D2：是否掐断 VLM 主干的语言路径
- 这是 C2 能否成立的关键。
- **当前倾向（保险版）**：保留 VLM 双输入（视觉+语言），但通过反事实测试（§6 E1）来诊断 M3 是否被绕过；若被绕过再加约束。
- **若 E1 不通过的后备**：训练时引入 dropout——以一定概率屏蔽 VLM 的语言输入，迫使模型也学会从 M3 通路获取语言信号

### D3：是否同时引入第二个时间尺度
- **当前倾向**：先不做。先把"语言条件化短时压缩"做扎实再说。
- 长时尺度可作为下一篇工作的延续（参见 §9 后续路线图）

### D4：辅助损失的形式
- **当前倾向**：从 \(H\) 反推任务分类（最简单、最直接强迫 \(H\) 含任务信息）
- 备选作为消融：同任务对比损失、从 \(H\) 重建语言 token

### D5：训练数据组织 ✅ 已锁定
**方案**：LIBERO 四套件联合训练（Spatial + Object + Goal + Long 全部 40 任务）

**理由**：
1. 不同套件的语言模式差异显著（方位词 / 物体属性 / 目标位置 / 复合动作），这是 LIBERO 内**唯一能拉开语言信号熵**的方式——同套件内指令几乎是模板化的，无法支撑任务条件化的学习
2. 跨套件泛化是 C1/C3 的天然测试场——单套件训练无法证明语言条件化的有效性
3. E5（跨任务一致性分析）只在多套件下才有可对比性

**训练配置**：
| 项 | 配置 |
|---|---|
| 训练数据 | 4 套件 × 10 任务 × 50 demos = 2000 demos |
| Batch 采样 | 4 套件**等概率**采样（防长套件主导）；套件内任务均匀采样 |
| 训练步数 | 30K（沿用 MoSA-VLA 协议，可比性） |
| GPU | 8 × L20 (48GB) |

**评估协议**：
- 每个 checkpoint 在 4 套件上独立评测，每套件 10 任务 × 50 episodes = 500 rollouts
- 总计 2000 rollouts/checkpoint
- 报告：每套件成功率 + 4 套件平均 + **任务间方差**（C4 一致性的硬指标）

**进一步（可选）**：指令改写增强（同语义不同表述）——只在 E1 反事实测试不通过时启用

### D6：是否引入两阶段训练（借鉴 CoPE-VideoLM）
- **背景**：CoPE-VideoLM 的 Δ-Encoder 先做 SigLIP RGB token 重建预训练再 SFT，**没这步性能掉 4pp**。说明把 codec 输出"翻译"到 VLM 视觉 token 空间的预训练是必要的对齐工序。
- **当前倾向**：引入两阶段训练——
  - 阶段 1：用重建损失（M3 输出的摘要词元 \(H\) 重建 VLM 视觉 token 或 SigLIP RGB token）预训练 M1+M2+M3
  - 阶段 2：接入完整 VLA 做端到端动作预测 + 语言条件化训练
- 好处：对齐预训练让 codec 输入与 VLM 语义空间一致后，再引入语言条件，效果更好理解；同时这是 MoSA-VLA 没做过的工程贡献
- **执行策略**：若时间紧可先跑单阶段拿基线，再用两阶段做"训练范式增强"消融
- **关联实验 E6**：两阶段 vs 单阶段对照，预期至少 +1pp（动作精度）+ 收敛速度更快

### D7：是否加入 codec 残差分支（MV+residual 而非仅 MV）
- **背景**：MoSA-VLA 只用了 MV；CoPE-VideoLM 用 **MV+残差**双分支，残差捕获 MV 无法表达的"块级像素修正"（如纹理变化、轻微变形）。HiF-VLA 也只用 MV。机器人场景下接触/形变信息可能恰好藏在残差里。
- **当前倾向**：M1 增加残差提取，参照 CoPE-VideoLM 的双分支设计——MV 分支保持现状（块级位移）；残差分支用类似截断 ResNet 处理像素修正图，两路输出在 M2 之前合并
- **额外消融维度**："MV-only vs MV+residual" 对比可作为论文中段的实验论据
- **工程开销**：ffmpeg 提取残差与 MV 是同一管线下的副产物，工程改动很小
- **关联实验 E7**：MV-only / residual-only / MV+residual 三档消融

### D8：Stage 2 的压缩力度——空间还是时间？
- **背景**：Stage 1 输出已经是稀疏 patch（跨 T 帧有 N_kept 个 patch）。Stage 2 怎么进一步压？
- **当前倾向**：**空间 + 时间联合**——先用语言派生 query 对每帧的 patch 做加权（空间筛），再对 T 帧的加权结果做 K 个槽汇聚（时间压）
- 优点：两步都被语言条件化；最终输出固定 K 个词元，保持 MoSA-VLA 的 K-summary 工程优势，但每个槽都是空间+时间双维条件化的产物

### D9：Stage 2 选 patch 是 hard 还是 soft？
- **当前倾向**：语言派生 query + cross-attention（端到端可微，槽的可解释性强）——与 D1 倾向一致

### D10：H 是否进入 VLM backbone？关键架构选择

> **核心问题**：Stage 2 输出的 K 个摘要词元 H 是 **走旁路**（cross-attention 注入动作查询，沿用 MoSA-VLA），还是 **进 VLM 输入**（与视觉 patch 和文本 token 一起被 VLM 处理）？

| | Option A（旁路） | Option B（进 VLM） |
|---|---|---|
| 数据流 | H → MHA(Q, H) → 动作头 | H 拼到 VLM 输入 → VLM 内部加工 → Q → 动作头 |
| H 与语言的二次融合 | 无（语言只在 Stage 2 做一次） | 有（VLM 内每层 attention 再融合一次） |
| 同行参考 | HiF-VLA（AdaLN，不进 VLM）、MoSA-VLA | π0.7、CronusVLA、MEM、MemoryVLA、CoPE-VideoLM |
| HiF-VLA 担心的事 | 避免破坏 VLM 视觉—语言对齐 | π0.7 用 block-causal masking + observation 双向注意力解决了 |
| VLM 计算开销 | 不增加 | 增加 K 个 token（K=8 实际可忽略） |
| 工程改动 | 最少（沿用 MoSA-VLA） | 需改 VLM 输入处理（参考 π0.7 实现） |

- **当前倾向**：**Option A**——尤其 backbone 是 Qwen3-VL-0.8B（小模型）时，A 的优势比 4B 时更明确：
  1. **小 VLM 容量稀缺**：0.8B 仅 18–24 层 transformer，把容量分给 history token 等于拖累当前帧理解
  2. **预训练对齐更脆弱**：小模型层少、注意力头少，输入分布扰动直接传到下游
  3. **π0.7 走 B 的理由不适用**：5B (= 4B VLM + 860M action expert) 有冗余吸收扰动，0.8B 没有
  4. **HiF-VLA 担心的对齐破坏问题在小模型上更严重**——HiF-VLA 用 AdaLN 与 action expert 的设计正是为了避免污染 VLM
- **关联实验 E11**：Option A vs Option B 直接对比；对 0.8B 而言，预期 A 显著优于 B，结论本身是"小型 VLA 部署友好"的有效论据
- **论文叙事增强**：可以这样讲——"我们在 0.8B VLM 上证明：**任务条件化的轻量旁路（A）≥ 任务无关的 VLM-内置历史（B）**，这是 π0.7-style 路线在小模型部署时的反例"

### D11：动作头的具体实现形式

> **背景**：π0.7（860M）、ABot-M0（0.16B DiT）都用 flow matching；HiF-VLA / MoSA-VLA 用 L1 回归。对小型 VLA（0.8B VLM）合适的中等方案是 **100M flow matching DiT** 或 **100M transformer + L1 回归**。

**候选方案**：

| 方案 | 参数 | 损失 | 推理 | ICRA 同行对齐 |
|---|---|---|---|---|
| **B（推荐起点）：100M Transformer block + L1** | 100M | L1 | 1 次前向 | HiF-VLA |
| **C（推荐升级）：100M DiT + flow matching（动作空间）** | 100M | reweighted MSE on velocity | 4 步 Euler | π0、ABot-M0 |

**当前倾向**：第一阶段方案 B 拿基线 → 第二阶段方案 C 升级。

**为什么不一开始就做 C**：方案 B 是 1 次前向 + L1，非常稳定，能最快出第一个数字验证 HTCS 的核心 claim（Stage 1+2 任务条件化是否 work）。**先排除"动作头是瓶颈"的可能性**，再升级到 flow matching。

**为什么后续要升级到 C**：
- π0 / ABot-M0 已证明 flow matching 在长 chunk 上 +9%（chunk=30 时显著）
- 多模态动作分布更好（manipulation 多种合法轨迹）
- ICRA 评审熟悉 flow matching action head，避免"用过时的 L1"质疑

**方案 C 实现细节**（参考 ABot-M0 / π0）：
- **DiT 6 层**：self-attn（chunk 内）+ cross-attn（attend Q'）+ MLP
- **输入**：噪声动作 chunk (B, 8, 7) + 时间步 τ + 条件 Q' (B, 8, 1536)
- **损失**：\(\mathcal{L} = w(\tau)\|\hat{v} - v_{\text{gt}}\|^2\)，\(w(\tau) = 1/(1-\tau)^2\)
- **推理**：4 步 Euler 积分

**关联实验 E12**：方案 B vs C 对比，找出在 0.8B VLM 上的甜蜜点。

### D12：Stage 1 saliency 函数如何升级使其贡献本工作？

> **背景**：当前 Stage 1 完全借用 OneVision-Encoder（纯 codec saliency），是 novelty 评分最弱的一环。需要让 Stage 1 也成为本工作贡献，但**不引入 proprioception**。

**当前倾向：Language-Modulated Saliency Parameters**（不需要本体信息）

让语言**在参数级**条件化 codec saliency 公式：

\[
s_{i,j,t} \;=\; \alpha(\ell)\cdot\|\text{MV}\|_2 \;+\; \beta(\ell)\cdot|\text{Residual}|
\]

\(\alpha(\ell), \beta(\ell)\) 由小 MLP 从语言 embedding 派生：
- **"推"类任务**：α 大（看大幅运动）
- **"细致放置"类任务**：β 大（看接触/形变残差）

**叙事核心**：
- **层级化 = 参数级语言条件（Stage 1）+ 结构级语言条件（Stage 2）**——不依赖任何本体信息
- 论文卖点：**首次显式分离参数级与结构级语言条件化**——参数级决定"看哪种运动"，结构级决定"看哪些 patch"

**为什么不依赖 proprio 也好**：
- 部署友好：不需要同步 proprioception 数据
- 跨平台通用：人类示范视频也能用（无 proprio）
- 与主线契合度更高：所有任务条件化都来自**唯一信号源（语言）**，叙事更纯

**关联实验 E13**：纯 OneVision saliency vs language-modulated saliency 对比，验证 \(\alpha(\ell), \beta(\ell)\) 是否真随任务变化（可视化跨 4 套件的 α, β 值分布）

### D13：是否在 Stage 1 输出端拼接 codec 信息？

- **背景**：当前 Stage 1 输出仅是稀疏 RGB patch；MV/Residual 信息只在 saliency 评分时被用过一次就丢弃。可以让保留的每个 patch token 与其对应的 MV/Residual 信息**显式拼接**，形成 motion-aware patch。
- 形式化：\(P'_{i,j,t} = [P_{i,j,t};\ \text{MV}_{i,j,t};\ \text{Residual}_{i,j,t}]\)，再过线性投影对齐 ViT 维度
- **当前倾向**：试一把，ROI 不确定但实现成本低。如 E14 显示有用就加进 paper。

### D14：Stage 2 的细粒度筛选机制如何优化？

> **背景**：当前 Stage 2 是最朴素的"语言池化 → 派生 K query → 标准 MHA"。这里列三个必做的优化方向。

#### 优化 14.1：K slot 从语言 token 序列派生（不 pool）
- 现状：`slots = SlotProjector(mean_pool(ℓ_emb))` —— 池化丢失语言结构
- 改进：`slots = MHA(Q=learnable_K_queries, K=ℓ_emb, V=ℓ_emb)` —— K 个 slot 各自从语言序列拉取不同切片
- 收益：每个 slot 携带不同语义切片（动词/物体/空间）；直接支撑 C3 跨任务可区分性
- 成本：极低（替换一个 module）
- **必做**

#### 优化 14.2：Slot Attention 竞争性 softmax
- 现状：标准 MHA 的 softmax 沿 patch 维归一——不同 slot 可能 attend 同一批 patch（冗余风险 R6）
- 改进：Slot Attention（Locatello 2020）的 softmax **沿 slot 维归一**——每个 patch 必须被分配给某个 slot，强制 slot 互不重叠
- 收益：从机制上保证 K 个 slot 输出语义独立
- 成本：低（替换 softmax 维度 + 标准化）
- **必做**

#### 优化 14.3：Stage 1 saliency 作 Stage 2 attention bias
- 现状：Stage 1 算完 saliency 选完 patch 就丢了；Stage 2 中所有 patch 一视同仁
- 改进：\(\text{Attn}(Q, K, V) = \text{softmax}\big(\frac{QK^\top}{\sqrt{d}} + \lambda \cdot s\big)\,V\)，其中 \(s\) 是 Stage 1 saliency
- 收益：信息无损传递；强化层级化叙事——两阶段不是简单串联，而是 Stage 1 持续给 Stage 2 提供 prior
- 成本：极低（一行代码）
- **必做**

#### 推荐组合
**14.1 + 14.2 + 14.3 同时上**——三个低成本改造，把 Stage 2 从"标准 MHA"升级为"语言结构化 + 竞争性 + 层级感知"复合机制。

#### 关联实验 E15
逐项消融 14.1 / 14.2 / 14.3，看每个组件对最终性能的贡献以及对 E5（跨任务一致性）/ E9（patch IoU 差异性）的影响。

### D15：M4 融合 / M5 动作头 是否需要强化？ ✅ 已锁定

> **决策**：**M4 不强化（保持单层 cross-attention + LayerNorm + 残差）；M5 按 D11 升级为 100M 轻量 action expert**。

**核心论点**：HTCS 与同行（π0.7、HiF-VLA）的**任务条件化位置**不同——
- 同行：任务理解在末端（重型 action expert / joint expert 补救任务无关历史）
- HTCS：任务理解在前端（Stage 1+2 已完成任务条件化）

→ **前端做了任务条件化，末端不需要重型 expert 兜底**。这是完整的设计哲学，不是凑省。

**为什么 M4 保持单层**（4 个理由）：
1. **稀释主线**：M4 加复杂融合会模糊"增益来自压缩"的叙事
2. **混淆 ablation**：M4 简单让 E10（去 M3）的归因更干净
3. **违背小模型叙事**：M4+M5 总参数膨胀会突破 0.8B 小 VLM 的"轻量"定位
4. **MoSA-VLA 已证可行**：同款 M4 在 LIBERO-Long 达 96.2%，不是瓶颈

**M5 升级到 100M action expert（D11）的理由**：0.8B VLM 容量小，2 层 MLP 不够吸收动作回归复杂度；100M expert 是规模与表达力的甜点。

**论文里要写出来的设计原则**（可作为方法节的 closing paragraph）：
> "Unlike π0.7 and HiF-VLA which adopt heavy task-aware fusion experts to compensate for task-agnostic history encoding, HTCS pushes task conditioning to the compression stages (Stages 1 and 2). This allows the fusion (M4) and action head (M5) to remain lightweight without sacrificing capability — the model's task-relevant capacity is concentrated in the compression pipeline rather than in late-stage fusion."

**禁止的"过度优化"清单**（避免 review 时被问偏）：
- ❌ 在 M4 加 saliency bias / 语言条件化（边际收益低，混淆叙事）
- ❌ 把 M4 改为多层 transformer decoder
- ❌ 把 action expert 加大到 200M+（失去小模型卖点）

> **没做这些就不能说语言条件起作用了。** 这一节是论文能否说服 reviewer 的硬证据。

| ID | 实验 | 目的 | 期望结果 |
|---|---|---|---|
| **E1** | **反事实指令替换** | 推理时把语言换成无关/随机指令，对比成功率 | 性能**显著下降**——说明语言被真用上了 |
| E2 | M3 ablation：移除语言条件 | 退化为 MoSA-VLA 基线 | 性能下降，定位增益来源 |

| E4 | 辅助损失消融 | 关闭 D4 的辅助损失看是否还成立 | 关闭后增益保留 → 结构本身够强 |
| E5 | 跨任务一致性分析 | 不同任务在 M3 处的注意力分布是否真的不同 | 同任务相似、跨任务远离 |
| E6 | **两阶段 vs 单阶段训练**（关联 D6） | 验证 codec 输出 → VLM 语义空间对齐预训练的必要性 | 两阶段 ≥ 单阶段 +1pp；同时收敛步数更少 |
| E7 | **codec primitives 消融**（关联 D7） | MV-only / residual-only / MV+residual 三档对比 | 揭示残差对决策是否有贡献，可形成"完整 codec primitives"卖点 |

| **E9** | **Stage 1 vs Stage 2 patch 集合差异性**（关联 C3） | 可视化两阶段选出的 patch 集合 IoU；统计跨任务下 Stage 2 选 patch 是否随指令变化 | IoU 不应过高（< 0.5），Stage 2 在不同指令下应选出不同 patch；否则 Stage 2 冗余 |
| **E10** | **去掉 Stage 2 退化为 OneVision-Encoder + 简单池化** | Stage 1 输出直接 mean-pool 或 attention pool 进 cross-attention | 性能应显著低于完整版（说明 Stage 2 不仅仅是凑结构） |
| **E11** | **H 旁路 vs 进 VLM**（关联 D10） | Option A（cross-attn 注入 Q）vs Option B（拼到 VLM 输入），其余完全一致 | 0.8B VLM 上预期 A ≥ B；对比 π0.7 风格的 B 路线，得出"小模型部署应走 A"的结论 |
| **E12** | **MLP 动作头 vs 轻量 action expert**（关联 D11） | 2-layer MLP vs ~100M transformer action expert，其余完全一致 | 验证 0.8B VLM 是否需要专门的 action expert 来"补血" |
| **E13** | **Language-modulated saliency 消融**（关联 D12） | 固定权重 saliency vs 语言调制权重 \(\alpha(\ell), \beta(\ell)\)；可视化跨 4 套件的 \(\alpha, \beta\) 分布 | 验证语言调制权重是否真随任务变化（参数级条件化的合法性证据） |
| **E14** | **Patch 拼接 codec 信息消融**（关联 D13） | RGB patch only vs RGB+MV+Residual 拼接 | 验证 Stage 1 输出端富化是否带来增益 |
| **E15** | **Stage 2 优化逐项消融**（关联 D14） | 朴素 MHA vs +14.1（slot 来自语言序列）vs +14.2（Slot Attention）vs +14.3（saliency bias）vs 三者组合 | 验证 Stage 2 三个低成本优化各自贡献，及对 E5/E9 的间接影响 |

> **E1 是硬指标**。开发到第一版原型时立刻跑，如果性能不掉就回去加约束，不要继续往下做。

## 7. 与已有工作的差异化定位

| 对照工作 | 它做了什么 | 本工作差异 |
|---|---|---|
| **OneVision-Encoder** | codec patch selection（任务无关单阶段） | **Stage 1 借框架但升级 saliency 为语言调制权重**（参数级语言条件）；Stage 2 加结构级语言条件二次压缩 |
| **HiF-VLA** | MV 作输入特征 + AdaLN 调制 decoder（任务无关） | 本工作用 MV 做 patch selector（不是 feature input），机制完全不同 |
| **CoPE-VideoLM** | I/P-frame 二分作 token 分配（任务无关） | 本工作不依赖 I/P 二分，用语言作第二阶段筛选；输出固定 K 槽适合 VLA cross-attention |
| **π0.7 / MEM** | 6 帧短时历史 + RGB patch dropping，进 VLM；多模态 prompt 条件化（任务无关历史） | 本工作的语言条件化在**历史编码内部**而非 prompt 层面；codec selection 比 raw patch dropping 更精准；K-summary 输出比 same-as-single-frame 预算更紧凑 |
| **MoSA-VLA**（基线） | 单阶段、MV-as-feature、任务无关摘要槽 | 改为两阶段、Stage 1 借用 OneVision、Stage 2 任务条件化 |
| **VLA-Pruner / EfficientVLA** | 推理期、任务感知词元裁剪 | 本工作训练期可微 + Stage 2 由语言派生 query 主导 |
| **MEM / MemoryVLA / ReMem-VLA** | 多尺度记忆 | 本工作单尺度，但 Stage 1+2 串联结构是新的 |

> **一句话定位**：本工作首次提出 **Hierarchical Task-Conditioned Selection (HTCS，任务导向的层次筛选)**——把语言条件化在 VLA 历史压缩中按 granularity 分为参数级（决定看哪种运动）和结构级（决定看哪些 patch）两级，分别在 codec saliency 函数和后续二次压缩中落地。这是当前 8+ 个 codec/memory-based VLA 工作集体未做的 framing 创新，**且仅依赖语言信号，不需要 proprioception**——使其在跨平台部署和人类示范视频场景下保持适用。

### 与 OneVision-Encoder 的边界（必须写清楚以避免被指剽窃）

- **借用部分**：HEVC GOP 配置、I-frame 全 patch 保留、P-frame 按 saliency 排序、3D RoPE。这些**直接引用 OneVision-Encoder 并明确标注**。
- **本工作贡献的 Stage 1 升级**：把 saliency 函数从固定权重（\(\|\text{MV}\| + \gamma|\text{Residual}|\)）升级为**语言调制权重**（\(\alpha(\ell)\|\text{MV}\| + \beta(\ell)|\text{Residual}|\)）。这是参数级语言条件化——OneVision-Encoder 没有也不需要（他们做通用 video LLM，没有任务指令信号）。
- **本工作贡献的 Stage 2**：结构级语言条件化二次压缩，输出固定 K 摘要词元。
- **本工作贡献的 framing**：双 granularity 语言条件压缩（参数级 + 结构级）——这是把"语言条件化"按 granularity 分离的概念创新，类似 OneVision-Encoder 的"many×sparse 颠倒"是概念创新。
- **额外贡献**：方法不依赖 proprioception，跨平台/跨形态部署友好，可用于人类示范视频。

## 10. 论文必答问题清单（FAQ — Reviewer Questions）

> **写论文时 Intro 和 Method 节必须主动回答下列问题**。每个问题列出回答要点 + 实验/数据支撑。

### Q1：为什么需要历史信息？
- **核心 claim**：VLA 任务本质非马尔可夫，但**历史不能直接消化**——必须经任务相关压缩
- **支撑**：MoSA-VLA 朴素 8 帧堆叠 70.8% vs 单帧 94.6%（剪刀差）；MoSA-VLA T 消融在 Long 套件上 T=8/16 优于 T=32（更多历史反而有害）
- **关键转折**：把"为什么需要历史"和"为什么需要 HTCS"逻辑串起来——历史是必要的，但必须配套合适的压缩

### Q2：为什么用 codec 筛 patch（而不是学到的 saliency / 光流 / 物体检测）？

| 替代方案 | 为什么不选 |
|---|---|
| 学到的 saliency 网络 | 加参数；训练不稳定；DMC-Net 已验证不显著优于纯 codec |
| 光流估计 | 计算成本 2–4× MV；dense 输出与 patch grid 不对齐 |
| 物体检测 | 需检测器/标签；定位物体不捕获运动 |
| VLM 自身 attention | 任务无关；需走完 ViT 才能拿到，违背提前压缩目标 |

- **codec 优势**：零参数、零训练、块级与 ViT patch 对齐、CoViAR 系列 8 年验证、与稀疏性假设天然契合

### Q3：为什么两阶段（参数级 + 结构级），不是单阶段？
- 单凭 codec → 漏掉静态但任务关键的 patch（"放到柜子顶部"——柜子可能不动但关键）
- 单凭语言 → 受无关运动干扰，且需要全帧 ViT 才能 attention 到 patch，效率差
- 两者正交互补——支撑实验是 E9（patch IoU < 阈值）

### Q4：为什么用语言作为条件信号？
- 语言指令是 VLA 任务定义本身，不可绕开
- 天然可用（不需额外标注或传感器）
- 不依赖 proprio → 跨平台 / 人类示范视频通用

### Q5：为什么参数级和结构级各占一阶段？
- 参数级（标量权重）粗粒度、低成本，适合 Stage 1
- 结构级（K query）细粒度、高表达力，适合 Stage 2
- 先粗后细级联是计算效率与表达力的合理权衡

### Q6：为什么用 MV + Residual 而不只用 MV？
- MV 捕获块级位移（"动了多少"）
- Residual 捕获运动补偿后的剩余差异（"形变/接触/纹理变化"）
- manipulation 接触瞬间 MV 小但 Residual 大——两者互补
- 实验支撑：E14 的 MV-only / Residual-only / both 三档消融

### Q7：为什么 H 走旁路而不进 VLM（Option A vs B）？
- 0.8B VLM 容量稀缺，加 K 个 history token 占用相对容量大
- 预训练对齐脆弱，干扰直传下游
- HiF-VLA 自承的"避免破坏视觉—语言对齐"在小模型上更严重
- **核心反 π0.7 论点**：π0.7 的 Option B 在 5B 规模成立，但小模型上 Option A 更优——E11 提供硬证据

### Q8：为什么用 LIBERO 4 套件联合而不是单套件？
- 同套件指令熵太低（Spatial 内 10 任务模板几乎一样），无法支撑任务条件化的学习
- 4 套件联合让语言鉴别力跨任务类别拉开（方位词/物体/目标位置/复合动作 4 种模板）
- 跨套件泛化是 C1/C3 的天然测试

### Q9：为什么是这个时间窗口（T=16）？
- π0.7 用 6 帧 1s，HiF-VLA 用 8 帧——VLA 短时记忆 6–16 帧是同行共识
- T=16 沿用 MoSA-VLA 协议保证可比性
- T=32 在 MoSA-VLA 消融已证明退化（不是越多越好）

### Q10：HTCS 与 HiF-VLA 的差异是什么？
- HiF-VLA：MV 当 input feature + AdaLN 调制（任务无关）
- HTCS：MV 当 saliency selector + 双 granularity 语言条件（任务条件化）
- 实验对比：E11 + 直接复刻 HiF-VLA 的 hindsight encoder 作为 baseline
